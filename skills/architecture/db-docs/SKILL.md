# Database Docs with tbls

ER diagrams are **generated from the database, never written by hand**. tbls reads Postgres's system catalogs (tables, columns, PKs, FKs, indexes, enums) and writes Markdown pages plus SVG diagrams into `docs/database/`. Because it re-reads the database each run, the docs follow every schema change.

- tbls only **reads** the database. It never changes it.
- It runs as a Docker image (`ghcr.io/k1low/tbls`, pinned version), so the only requirement is Docker.
- The connection string never goes in the repo. The runner script reads it from `TBLS_DSN` or the project's `DATABASE_URL`.

## Files in this skill

| File | Copy to | Purpose |
|---|---|---|
| `templates/db-docs.mjs` | `<project>/scripts/db-docs.mjs` | Runner: resolves the DSN, rewrites `localhost` for Docker, strips Prisma-only params, runs tbls with `-c .tbls.yml` |
| `templates/tbls.yml` | `<project>/.tbls.yml` | Config: output path, ER settings, excludes, lint rules, comments |

## Workflow A: Set up in a new project

1. **Check prerequisites.** Docker is running, the Postgres container is up and migrated, and the project has `DATABASE_URL` in `backend/.env` or `.env`. If the env file lives elsewhere, edit `ENV_FILES` in the script.
2. **Copy the templates** from this skill folder into the project (paths above).
3. **Edit `.tbls.yml`:**
   - Set `name` to the project name.
   - `exclude`: the migration bookkeeping table (`public._prisma_migrations` for Prisma, `public.schema_migrations` for others). If pgvector is installed, uncomment the pgvector function block and confirm none of the patterns match a real table.
   - `lint.unrelatedTable.exclude`: tables that are standalone by design (webhook/event logs).
4. **Add npm scripts** to the root `package.json`:
   ```json
   "db:docs": "node scripts/db-docs.mjs doc",
   "db:docs:check": "node scripts/db-docs.mjs diff",
   "db:lint": "node scripts/db-docs.mjs lint"
   ```
5. **Generate:** `npm run db:docs`, then confirm `npm run db:docs:check` exits 0.
6. **Add the rule** to the project's `AGENTS.md` (Backend Standards), unless it already came from `plan-project`:
   > **Generated Database Docs:** `docs/database/` is generated by tbls from the live database. NEVER hand-edit it and NEVER hand-write Mermaid/Markdown ER diagrams. After any migration is applied, run `npm run db:docs` and commit `docs/database/` together with the migration. `npm run db:docs:check` must pass before schema work is finished. These commands are read-only, so they are exempt from the Hands-On Terminal rule.
7. **Report `npm run db:lint` findings** to the user. Do not fix them silently: fixes are schema changes and need a migration.
8. Commit `.tbls.yml`, `scripts/db-docs.mjs`, `package.json` and `docs/database/`.

## Workflow B: After a schema change

```
migration applied (e.g. npx prisma migrate dev)  →  npm run db:docs  →  commit migration + docs/database/ together
```

- Run `npm run db:docs:check` before saying schema work is done.
- If a table was dropped, `--rm-dist` (already in the script) removes its stale pages.

## Workflow C: Answering questions about the schema

Read `docs/database/README.md` (all tables + full diagram) and `docs/database/public.<table>.md` (columns, constraints, indexes, relations) instead of re-deriving the schema from migration files. Regenerate first if `db:docs:check` fails.

## Adding descriptions

Comments appear in the docs and inside the diagram boxes.
- **Plain SQL projects:** `COMMENT ON TABLE orders IS '...';` in a migration.
- **Prisma projects:** Prisma does not write `COMMENT ON`, so add them under `comments:` in `.tbls.yml` (example in the template).

## Gotchas

- **`.tbls.yml` is not auto-discovered inside the container.** The script always passes `-c .tbls.yml`. Keep that if you call Docker by hand.
- **`localhost` inside the container is the container itself.** The script rewrites it to `host.docker.internal`.
- **Don't export PNGs.** `tbls out -t png` renders the relationship lines as filled black blobs. The committed SVGs are correct.
- **`tbls out -t config` prints the DSN with its password.** Don't paste that output anywhere.
- **The DB must be running and migrated.** tbls documents what is in the database, not what is in the migration files.

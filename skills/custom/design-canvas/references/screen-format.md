# Screen Format — Files, Folders & Rules

Every artboard is a plain, self-contained HTML file. No React, no build step, no framework.
This keeps screens fast to generate, easy to review, and trivially translatable to any stack.

---

## 1. Folder Layout (in the project root)

```
design/
├── brief.md            ← direction, signature element, scope, motion (Step 1)
├── tokens.css          ← token bridge (see §2) — the ONLY place hex values may appear
├── kit.css             ← shared component classes (buttons, chips, cards, inputs, nav, sheet, .ph)
├── canvas.html         ← the viewer — copied from the skill's assets/, never edited by hand
├── canvas.js           ← the manifest: which screens exist, groups, sizes, status, notes
├── review.md           ← critique log (one entry per critique round)
├── screens/
│   ├── _kit/components.html          ← the component sheet (Step 2)
│   ├── <group>/<screen>.html         ← e.g. guest/menu-home.html
│   └── <group>/<screen>--<state>.html← state variants, e.g. guest/cart--empty.html
└── shots/              ← generated by scripts/shoot.mjs (PNG + report.md); add to .gitignore
```

Naming: lowercase kebab-case, no spaces. `<group>` = a user role or flow (`guest`, `staff`, `admin`, `marketing`).
State variants use a double hyphen: `checkout--error.html`, `orders--loading.html`.

## 2. Tokens — One Source of Truth

The app's token file (written by `frontend-design`, e.g. `frontend/src/styles/tokens.css` or `src/app/tokens.css`) is the single source of truth.
It must contain **only** the Google Fonts `@import`, `:root { … }` variables and `[data-theme="dark"] { … }` overrides — no Tailwind directives, no resets — so plain HTML can load it.

`design/tokens.css` is a one-line bridge to it:

```css
@import url("../frontend/src/styles/tokens.css");
```

If the app is not scaffolded yet, `design/tokens.css` holds the tokens directly; at handoff they move into the app's token file and the bridge line replaces them.

**Token naming (CSS variables):** kebab-case of the semantic role names from `frontend-design`:
`--bg-canvas --bg-surface --bg-card --bg-card-hover --text-primary --text-secondary --text-muted --accent-primary --accent-secondary --btn-primary --btn-hover --btn-text --border-subtle --border-focus --state-success --state-warning --state-error --state-info`
plus the non-color tokens: `--font-* --text-xs…--text-6xl --leading-* --tracking-* --weight-* --space-* --radius-* --shadow-* --dur-* --ease-* --z-* --touch-min --container-max --scrim`.

If a screen needs a value that has no token: **stop, add the token to the token file, note it in `review.md`, tell the user.** Never inline a raw value.

## 3. kit.css — Components Before Screens

`design/kit.css` holds every reusable piece, written with tokens only:
`.btn .btn--primary .btn--secondary .btn--ghost .btn--icon`, `.chip`, `.card`, `.field / .input / .label / .hint / .error`, `.badge--*`, `.nav-bottom`, `.topbar`, `.sheet`, `.toast`, `.skeleton`, `.ph` (labelled image placeholder), `.stepper`, plus domain components (e.g. `.menu-item`, `.order-ticket`, `.table-tile`).

Rules:
- Every interactive class defines `:hover`, `:focus-visible`, `:active`, `[disabled]`/`[aria-disabled="true"]`, and a loading modifier where relevant.
- Class names describe **what it is**, not how it looks (`.order-ticket`, not `.rounded-box-shadow`). These names become component names at handoff.
- Screens use kit classes first; a screen's own `<style>` holds **layout only** (grid, positioning, section spacing).
- Base reset + `body` font/color/background live at the top of `kit.css`.

The labelled placeholder:

```css
.ph { display:grid; place-items:center; background:var(--bg-surface); color:var(--text-muted);
      border:1px dashed var(--border-subtle); border-radius:var(--radius-md);
      font:var(--weight-medium) var(--text-xs)/1.3 var(--font-body); text-align:center; padding:var(--space-2); }
```
```html
<div class="ph" style="aspect-ratio:1/1">Photo — iced caramel latte · 1:1</div>
```
(`aspect-ratio` inline is allowed; colors/sizes inline are not.)

## 4. Artboard Sizes

| Device | Width × height | Notes |
|---|---|---|
| Phone | **390 × 844** | Default for consumer/mobile-first screens. Taller artboards (e.g. 390 × 1600) are fine for long scrolling screens — set `h` accordingly. |
| Tablet | 834 × 1194 | Only if the brief lists tablet as a target. |
| Desktop | **1440 × 900** | Set `h` to the full content height (e.g. 1440 × 1800) for long pages so reviewers see the whole page. |

The iframe in the canvas *is* the viewport, so `100vh` and media queries behave like a real device.

## 5. Screen File Template

Copy `assets/screen-template.html`. Required parts:

```html
<!doctype html>
<html lang="en" data-theme="light">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>G1 · Menu home — Brew Bari</title>
<link rel="stylesheet" href="../../tokens.css">
<link rel="stylesheet" href="../../kit.css">
<script>/* canvas passes ?theme=dark */(function(){var t=new URLSearchParams(location.search).get("theme");if(t)document.documentElement.dataset.theme=t;})();</script>
<style>
  /* layout only — every value is var(--…) */
</style>
</head>
<body>
  <main class="screen">…</main>
  <script src="https://unpkg.com/lucide@0.469.0/dist/umd/lucide.min.js"></script>
  <script>lucide.createIcons();</script>
</body>
</html>
```

Hard rules (each one breaks the canvas, the screenshot checks, or the handoff):
1. **No hex/rgb/hsl** anywhere except `tokens.css`. No raw px for spacing, font-size, radius, shadow — tokens only. (Exceptions: `1px` hairlines, `aspect-ratio`, layout widths like `minmax(0,1fr)`, `65ch`.)
2. **Semantic HTML:** `<header> <nav> <main> <section> <button> <a href> <label for>`; real `<input>`s in forms. Never a clickable `<div>`.
3. **Icons:** Lucide via `<i data-lucide="shopping-bag" aria-hidden="true"></i>`; icon-only buttons get `aria-label`.
4. **Images:** approved assets with `alt`, or `.ph` placeholders. No hotlinked stock photos.
5. **JS:** only the theme line, Lucide, and small `data-proto` prototype snippets (tabs, stepper, sheet toggle). No frameworks, no fetch.
6. **Relative paths only** so the folder works from `file://` and from a local server.
7. **Real content** (see craft.md §8). Bilingual products show both scripts somewhere on the key screens.
8. **Motion** with tokens, wrapped in `@media (prefers-reduced-motion: no-preference)` (see motion.md).

## 6. canvas.js — The Manifest

```js
window.CANVAS = {
  title: "Brew Bari",
  themes: ["light", "dark"],          // which [data-theme] values the tokens support; ["light"] if one
  groups: [
    {
      id: "kit", title: "Component kit",
      screens: [
        { file: "screens/_kit/components.html", title: "Kit · Components", w: 1440, h: 2200, status: "approved" }
      ]
    },
    {
      id: "guest", title: "Guest — phone (scan QR, no app)",
      screens: [
        { file: "screens/guest/menu-home.html", title: "G1 · Menu home", w: 390, h: 1600, status: "review",
          note: "Add to cart: button morphs into stepper (--dur-base), cart pill bumps (--ease-spring)." },
        { file: "screens/guest/cart--empty.html", title: "G3b · Cart — empty", w: 390, h: 844, status: "draft" }
      ]
    }
  ]
};
```

- `status`: `draft` (agent working) → `review` (passed self-critique, ready for user) → `approved` (user said yes) → `changes` (user asked for changes).
- `note`: motion spec, open questions, or what changed in this round. Keep it short.
- Order groups and screens in **user-flow order** — the canvas reads like the journey.

## 7. Viewing

- Simplest: open `design/canvas.html` directly in Chrome (file://).
- If the browser blocks file:// iframes or the token `@import` (some embedded browsers do), serve the **project root** (so `../frontend/...` resolves):
  `npx -y serve . -l 5178` → open `http://localhost:5178/design/canvas.html`
- Canvas controls: drag empty space (or hold **Space** and drag anywhere) to pan · **Ctrl/⌘ + wheel** to zoom · **F** fit all · **0** zoom 100% · click a frame title to open it in **focus mode** (← → to step through, Esc to close).
